TASK
Audit the requirement set as a whole. The full source document is in the system
message; the user message contains all extracted requirements and document-level
pre_detected_flags. Find defects that only appear at the level of the whole
document:

1. integration_mismatch — business requirements and technical specifications do
   not agree: a capability is declared but missing from the REST API; different
   units have no conversion rule; data types or HTTP statuses conflict; a general
   specification and its child API document disagree.
2. contradiction — logical conflicts between different requirement clauses.
3. duplicate — the same functionality is described by several requirements.
4. missing_requirement — unhandled edge cases: currencies, refunds, rounding,
   error texts.
5. incomplete_section — unfilled sections, template tables without marks,
   stubs such as "filled in by testers".
6. goal_coverage — whether the requirement set reaches the document's stated
   goal and which business goals are not covered.
7. ambiguous_requirement — a requirement is vague in a way that matters for the
   whole set.

Individual requirement wording is checked separately. Here describe only
document-level defects and relationships between sections.

If pre_detected_flags are present, apply the rules from the system message: keep
a confirmed flag, reject a false positive in rejected_flag_ids, and never
duplicate one flag with several findings.

OUTPUT FORMAT
Return only one valid JSON object without Markdown fences and comments:

{
  "findings": [
    {
      "evidence": ["verbatim quote from the source document"],
      "description": "what is wrong and why it blocks development or testing, in Russian",
      "category": "integration_mismatch | contradiction | duplicate | missing_requirement | incomplete_section | goal_coverage | ambiguous_requirement",
      "severity": "LOW | MEDIUM | HIGH | CRITICAL",
      "title": "short finding title in Russian",
      "related_req_ids": ["REQ-001"]
    }
  ],
  "rejected_flag_ids": ["LINT-001"],
  "summary": "brief state of the requirement set in Russian",
  "goal_coverage": "which document goals are covered and which are not, in Russian",
  "priority_actions": ["concrete step for the analyst, in Russian"]
}

For missing_requirement, incomplete_section and goal_coverage, quote the place
the gap belongs to: the goal, the section heading or a neighboring requirement.
If there are no set-level defects, return an empty findings array. The
application computes the final verdict.
